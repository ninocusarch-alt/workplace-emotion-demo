# “缓一缓”DeepSeek 长期记忆版设计

## 1. 产品目标

将现有规则驱动的职场情绪整理 Demo 升级为可持续使用的中文 AI 应用。产品面向 22–35 岁职场人士，在临时加活、汇报焦虑、跨团队沟通、工作受挫和职业倦怠等场景中，通过共情对话帮助用户识别情绪、澄清担忧并形成一个可执行的小行动。

本版本必须形成完整闭环：DeepSeek 生成真实回复、历史会话可回看、应用能够在后续对话中使用经过提炼的长期记忆，同时保留明确的安全和隐私边界。

## 2. MVP 范围

### 包含

- “我想先说说”“帮我理一理”“想想怎么办”三种对话模式。
- DeepSeek 中文多轮对话，而非预设回复。
- 同一浏览器下的匿名长期身份，无注册和登录。
- 历史会话列表、会话详情和继续对话。
- 每轮消息持久化以及会话标题、摘要和更新时间。
- 从对话中提炼可复用的长期记忆，并在新会话中按相关性注入。
- 用户可删除单次会话，也可清空全部历史和记忆。
- 高风险表达的本地优先识别、安全分流和模型安全约束。
- 对模型不可用、超时、输出异常和数据库失败的可理解提示。

### 不包含

- 账号体系和跨设备同步。
- 心理诊断、疾病判断、治疗建议和紧急救援替代。
- 向量数据库、知识库检索、文件上传或复杂智能体工作流。
- 运营后台、付费系统和社交分享。

## 3. 推荐架构

应用继续使用现有 vinext / Sites 架构。浏览器只保存随机生成的匿名用户令牌；业务数据保存在 Sites D1 数据库。DeepSeek API 只能由服务端路由调用，密钥通过服务端环境变量 `DEEPSEEK_API_KEY` 提供，不能返回给浏览器或写入仓库。

DeepSeek 使用官方 Chat Completions 接口和 `deepseek-v4-flash`，关闭思考模式以降低延迟和输出成本。模型请求包含稳定的产品系统提示、当前对话最近消息、相关长期记忆和必要的安全约束。产品不依赖 DeepSeek 服务端保存上下文。

主要模块边界：

- `匿名身份模块`：生成高熵令牌，以安全 Cookie 保存，并在服务端将其哈希为数据库所有权标识。
- `会话模块`：创建、列出、读取、更新和删除当前匿名用户的会话。
- `消息模块`：按顺序保存用户和助手消息，提供最近上下文。
- `DeepSeek 客户端`：封装请求、超时、返回校验和错误映射。
- `记忆模块`：从对话中提炼结构化记忆，合并重复内容并提供相关记忆。
- `安全模块`：在模型调用前处理高风险关键词和边界规则，并限制模型生成诊断或替代专业支持的内容。
- `界面模块`：保留现有视觉语言，增加历史侧栏、记忆提示、加载/失败状态和删除确认。

## 4. 数据模型

### users

- `id`：匿名用户主键。
- `token_hash`：匿名令牌哈希，唯一。
- `created_at`、`last_seen_at`：创建和最近访问时间。

### conversations

- `id`、`user_id`：会话及所有者。
- `mode`：listen、clarify 或 action。
- `title`：从首次输入生成的短标题。
- `summary`：会话结束或达到一定轮数后生成的简短摘要。
- `status`：active 或 completed。
- `created_at`、`updated_at`。

索引覆盖 `user_id + updated_at`，用于历史列表倒序读取。

### messages

- `id`、`conversation_id`。
- `role`：user 或 assistant。
- `content`：消息正文。
- `created_at`。

索引覆盖 `conversation_id + created_at`，用于按时间读取会话。

### memories

- `id`、`user_id`。
- `category`：stress_source、preference、goal、coping_strategy 或 unresolved_issue。
- `content`：一条简短、可独立理解的记忆。
- `confidence`：模型判断的置信等级。
- `source_conversation_id`：来源会话。
- `created_at`、`updated_at`。

索引覆盖 `user_id + category + updated_at`。MVP 每位匿名用户最多保留 30 条活跃记忆，优先合并同类重复内容，避免记忆无限增长。

## 5. 核心数据流

### 开始或继续对话

1. 浏览器请求会话接口。
2. 服务端读取匿名 Cookie；首次访问时创建令牌和匿名用户。
3. 服务端校验会话归属，读取最近消息和该用户的长期记忆。
4. 用户输入先经过长度限制和风险识别。
5. 高风险内容直接进入安全分流，不调用普通职场陪伴提示。
6. 普通内容先写入数据库，再调用 DeepSeek。
7. DeepSeek 回复通过结构和内容检查后写入数据库，并返回界面。
8. 若模型调用失败，用户消息仍保留，界面提供重试，不写入伪造的助手回复。

### 形成长期记忆

在会话达到 6 条消息、用户主动结束会话或生成复盘卡时触发异步式记忆提炼。服务端要求 DeepSeek 返回 JSON，内容只允许落入五个既定类别。应用校验 JSON、过滤敏感身份信息、与已有记忆做规范化去重后再写入数据库。

新会话最多注入 8 条长期记忆，并优先选择与当前模式和最近输入相关的内容。完整历史不会无限追加到模型上下文。

### 删除数据

- 删除会话时，同时删除该会话消息；由该会话产生且未被其他会话再次验证的记忆一并删除。
- “清空我的数据”删除该匿名用户的全部消息、会话和记忆，并使本地匿名令牌失效。
- 所有删除操作均需明确确认，且服务端再次校验数据归属。

## 6. 对话与记忆策略

系统提示要求 DeepSeek：

- 使用自然、简洁的简体中文，一次只推进一个问题。
- 先复述和确认用户感受，再帮助区分事实、解释、担忧、需求和行动。
- 不假装了解未提供的信息；引用长期记忆时使用试探性表达，例如“你之前提到过……这次也有关吗？”
- 不替用户作职业决定，不鼓励冲动辞职，不对同事或领导作人格诊断。
- 在行动模式中优先给出十分钟内可开始、由用户本人控制的小行动。
- 不宣称自己是心理医生，不提供诊断和治疗建议。

长期记忆只保存对未来对话有帮助的稳定信息或反复出现的主题。一次性的情绪强度、未经用户确认的模型推测、真实姓名、公司名称、联系方式和其他不必要的身份信息不进入长期记忆。

## 7. 安全与隐私

- 高风险关键词命中后展示“联系可信任的人、前往有人陪伴的环境、必要时联系当地急救或报警服务”等安全分流信息。
- 系统提示继续覆盖隐性自伤、伤人、严重危机及过度依赖 AI 的情况，普通对话不得弱化紧急求助建议。
- 页面明确说明用途、数据会被保存、删除入口以及“不替代专业支持”的边界。
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`；数据库不保存明文匿名令牌。
- API 日志不记录完整情绪对话；错误记录仅保留请求标识、错误类型和时间。
- 服务端限制单条消息长度、每次读取数量和接口频率，防止滥用及意外成本。

## 8. 界面变化

首页保留三种模式入口，并新增“继续上次对话”和“历史记录”。桌面端采用可收起的历史侧栏，移动端使用抽屉。会话顶部展示当前模式和“已保存”状态；长期记忆被使用时，只提示“已参考你的过往记录”，避免暴露内部提示词。

历史列表展示标题、日期、模式和最后一句摘要。删除入口位于单次会话菜单；设置区域提供“清空全部数据”。原有复盘卡保留，但内容改由当前真实对话生成。

## 9. 错误处理

- DeepSeek 超时或服务异常：保留用户消息，显示“刚才没有回复成功”，允许原地重试。
- DeepSeek 返回空内容或异常格式：重试一次；仍失败则返回统一错误，不把异常文本写入历史。
- 数据库写入失败：不向用户显示“已保存”；阻止继续产生与数据库状态不一致的回复。
- Cookie 无效：创建新的匿名身份，不读取任何其他用户数据。
- 会话不存在或不属于当前用户：统一返回未找到，避免泄漏资源是否存在。
- 记忆提炼失败：不阻断主对话，在下一次满足条件时重新尝试。

## 10. 验收与测试

### 功能验收

- 三种模式均能获得 DeepSeek 生成的上下文相关回复。
- 刷新页面后仍能看到当前浏览器的历史会话。
- 新会话能以克制、可确认的方式引用此前形成的相关记忆。
- 用户可删除单次会话和清空全部数据。
- 浏览器端源码和网络响应中不出现 DeepSeek API Key。

### 自动测试

- D1 数据访问：归属校验、排序、级联删除、记忆数量上限和去重。
- 服务端路由：首次匿名身份、消息保存、模型失败重试、非法输入和越权访问。
- 提示与解析：有效 JSON、空内容、截断内容、未知类别和敏感信息过滤。
- 安全规则：明显与隐性高风险表达不进入普通对话流程。

### 产品评测

沿用项目的 30 条中文职场对话评测集，从共情准确性、追问相关性、行动可执行性、语言自然度、边界合规性和记忆引用准确性六个维度评估。记忆引用增加两条硬性标准：不得编造历史；不得把模型推测当作用户事实。

## 11. 成功标准

- 用户能够完成一次真实 AI 对话并在刷新后找回。
- 第二次会话能够正确利用至少一条经过确认的相关记忆。
- 删除后对应数据不可再次读取或注入模型。
- 高风险测试样本全部进入安全分流。
- API 与数据库异常都有清晰、可恢复的界面状态。
